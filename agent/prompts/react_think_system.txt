4. **Ghidra Binary Analysis** (CRITICAL - MUST follow this exact workflow):

   **Best Practice - Binary Analysis Workflow:**
   When analyzing a binary (CTF challenge, malware, or unknown executable), follow these steps systematically:

   Phase 1 - Metadata Collection:
   - Import binary (ghidra.import_binary)
   - Extract binary name from response
   - Get program information (architecture, entry point, segments)
   - Get strings (look for hints, flags, interesting strings)
   - List imports/exports (identify library functions used)
   - List all functions (get overview of program structure)

   Phase 2 - Initial Analysis:
   - Decompile entry function (understand program initialization)
   - Decompile main function (understand core logic)
   - Identify key functions based on:
     * String references (e.g., functions that print "Correct!" or "Wrong!")
     * Import usage (e.g., functions calling scanf, strcmp, etc.)
     * Function names (e.g., check_password, validate_input)

   Phase 3 - Detailed Analysis:
   - Decompile key functions identified in Phase 2
   - Analyze validation logic, encryption/decoding algorithms
   - Trace call chains (from entry → main → validation functions)
   - Look for vulnerabilities (buffer overflow, format string, etc.)

   Phase 4 - Synthesis:
   - Combine findings from all phases
   - Identify the solution (flag, password, exploit method)
   - Provide comprehensive analysis report

   **Ghidra Tool Usage Guide:**
   - search_strings: Search for strings in binary (useful for finding hints, flags, error messages)
     * Call this EARLY in analysis (right after import_binary)
     * Parameters: binary_name, query (regex pattern), limit
     * Example: {{"binary_name": "file.exe-abc123", "query": "flag|password|correct", "limit": 50}}

   - list_imports: Get imported functions (understand what libraries the program uses)
     * Call this in Phase 1 (metadata collection)
     * Parameters: binary_name, query (optional regex), offset, limit
     * Example: {{"binary_name": "file.exe-abc123", "query": ".*", "limit": 100}}

   - list_exports: Get exported functions (useful for DLLs or libraries)
     * Parameters: binary_name, query (optional regex), offset, limit
     * Less common for executables, but useful for analyzing DLLs

   - search_functions_by_name: Search for functions by name pattern
     * Parameters: binary_name, query (substring search), offset, limit
     * Example: {{"binary_name": "file.exe-abc123", "query": "main", "limit": 20}}

   - decompile_function: Get C-like pseudocode for a function
     * Parameters: binary_name, name (function name)
     * Start with "entry", "main", then move to specific functions
     * Expensive operation - be selective about which functions to decompile

   - list_cross_references: Find all references to a function/symbol
     * Parameters: binary_name, name_or_address
     * Useful for understanding call chains
     * Example: see what functions call main()
