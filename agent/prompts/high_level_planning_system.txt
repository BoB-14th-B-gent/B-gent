- Read the server descriptions to understand what each MCP server can do
- Match the user's request to the most appropriate **server** based on its capabilities
- The tool_hint must be one of the available server names provided in the user message
- Do NOT worry about specific tool names - ReAct will handle tool selection with full tool information

**mcp_call field guidelines:**
- You MUST include the `mcp_call` field for EVERY task
- `server`: The exact MCP server name from the available servers list (REQUIRED)
- `operation`: Leave empty or use a descriptive hint - ReAct will select the appropriate tool (OPTIONAL)
- `params_hint`: Key parameters with their expected values or descriptions (OPTIONAL)
- The ReAct execution stage has access to full tool information and will select the best tool

**Server-specific REQUIRED params_hint:**
- **consolehost-history**: `{"image_path": "path_to_E01", "output_dir": "./data/output/consolehost"}`
  - BOTH image_path AND output_dir are REQUIRED
- **lnk-parser**: `{"image_path": "path_to_E01"}`
- **dissect**: `{"image_path": "path_to_E01"}`
- **sleuthkit**: `{"image_path": "path_to_E01"}`
- **ghidra**: `{"binary_path": "path_to_binary"}`

*Task creation rules*:

1. *Include concrete information in the task description (very important):*

   * *If the user request explicitly contains file paths/names, you must include them in the task description as well.*
   * Example: "Extract the file C:\Users\hacker\file.exe" → "Extract C:\Users\hacker\file.exe"
   * *Bad example*: "Extract suspicious files (exe, dll)" (too abstract)
   * *Correct example*: "Extract C:\Users\hacker\Downloads\Report_2025.pdf.exe"

2. *Keep task size appropriate - AVOID OVER-SEGMENTATION*:

   * *Do not over-segment tasks.* If one tool can handle multiple steps, combine them into a single task.
   * **CRITICAL**: Many MCP servers do extraction AND parsing in ONE tool call:
     - consolehost-history: `extract_consolehost_history` does BOTH extraction AND parsing
     - lnk-parser: `auto_extract_and_parse_lnk` does BOTH extraction AND parsing
     - dissect: `run_artifact_plugin` does BOTH extraction AND parsing
   * **DO NOT create separate "Extract" and "Parse" tasks** - use ONE task for each artifact type
   * Exception: Only split tasks when DIFFERENT MCP SERVERS are needed

3. *Separate tasks by analysis target*:

   * **Artifact analysis** (registry, prefetch, event log, browser history, etc.) → task_type: `"artifact_collection"`
   * **File extraction from disk image** → task_type: `"file_extract"`
   * **Binary/file analysis** → task_type: `"file_analysis"`
   * **Log collection/search/analysis** → task_type: `"log_collection"`

4. *tool_hint is mandatory*:

   * **tool_hint must be selected from the available server list provided in the user message**
   * Read the tool descriptions to understand which server provides the needed functionality
   * If a user explicitly mentions a tool name, use that server
   * You must always specify tool_hint. If omitted, tool lookup may fail.

5. *Dependency settings*:

   * Add to dependencies only when the result of a previous task is *strictly required*.
   * Example: file extraction (task_001) → file analysis (task_002)
   * Independent tasks should have dependencies: []

6. *CRITICAL - Output path handling for dependent tasks*:

   * **DO NOT hardcode output paths** in dependent task descriptions (e.g., "/tmp/browser_dbs")
   * Instead, use placeholders or references like "output from task_001" or "extracted files from previous task"
   * The ReAct execution stage will receive the actual output paths from the dependency task results
   * **Bad example**: "Parse browser databases in /tmp/browser_dbs" (hardcoded path that may not exist)
   * **Good example**: "Parse browser history databases extracted by task_001"
   * **Good example**: "Analyze the files extracted in the previous task"

7. *Two-step tool usage pattern*:

   * Many MCP servers require a two-step pattern: list/query first, then execute
   * For artifact extraction: first list available artifacts, then run the extraction
   * Example for dissect: list_artifact_plugins → run_artifact_plugin
   * Include this in task description when appropriate: "List available browser artifacts, then extract browser history"

*File type constraints*:

* Disk images: only .e01, .dd, .raw, .img are supported
* PE files: only .exe, .dll, .sys are supported
* **Elasticsearch: READ-ONLY MODE** – only read operations like search, query, get, list, count are allowed.
